# STAGES.md — этапы работ по сайту-витрине

Этапы взяты из `TZ.md` без изменений. Переход к следующему этапу — только после подтверждения пользователем.

## Проверка результата

Playwright отключён (`../AGENTS.md`, раздел 7). Проверка выполняется через MCP `chrome`, и перед каждым открытием сайта агент обязан остановиться и получить разрешение.

Дев-сервер запускается так (без обёртки npm, иначе `spawn EPERM`; привязка к IPv4 обязательна — по умолчанию Vite слушает только `[::1]`):

```
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
```

Адрес: `http://127.0.0.1:5173/`

Порт слушается только на IPv4-петле. Если в лог сервера попадает `file watcher error: EBUSY ... .tmpdir`, это не поломка приложения: так инструменты записи создают временные каталоги рядом с изменяемым файлом. Они исключены из слежения в `vite.config.ts` и внесены в `.gitignore`.

**Баг StrictMode: застрявшие анимации.** Кнопка CTA в Hero оставалась невидимой навсегда — `opacity: 0`, `transform: translateY(32px)`, то есть ровно стартовое состояние `gsap.from`, которое так и не проиграло. Причина: очистка эффекта вызывала `tween.kill()`, а `kill()` **не возвращает** элемент в исходное состояние — инлайн-стили стартового состояния остаются. В React StrictMode эффект выполняется дважды (setup → cleanup → setup): второй `gsap.from` читает уже испорченное текущее значение как конечное и анимирует 0 → 0. Заменено на `tween.revert()`, который снимает применённые стили. Проявлялось в dev и на любом повторном запуске эффекта.

**Разметка переведена на новый триггер.** `pinsFade` больше не стоит на `<tr>`: transform на строке таблицы ломает раскладку. Вместо него введён `rowsFade`, который анимирует у `<tbody>` только прозрачность строк, без transform.

- [ ] Подтверждение пользователем — смотрит в браузере сам

**Осознанные решения этого этапа:**

- **Фоны секций с 3D стали полупрозрачными.** Введены утилиты `bg-gradient-*-soft`, иначе непрозрачный фон секции перекрыл бы WebGL-слой. Hero сделан полностью прозрачным — градиент несёт фиксированная подложка.
- **Работаем на чистом Three.js, без `@react-three/fiber`.** R3F не входил в согласованный набор пакетов, поэтому рендерер, камера, свет и цикл отрисовки поднимаются вручную в `useDeviceScene`.
- **Ряд сравнения покачивается, а не вращается** (`MOTION.sway`): при полном обороте устройства вставали бы в профиль и переставали читаться.
- **Силуэты устройств пока остались** в разметке секций. Они дублируют 3D-сцену; убрать их стоит на Этапе 5, когда появится `ScenePoster` как полноценный запасной вариант.

### Проверка в браузере (выполнена)

Браузерный мост заработал, страница осмотрена вживую. Найдена и исправлена критическая ошибка:

- **`renderer.forceContextLoss()` в очистке эффекта убивал канвас.** В React StrictMode эффект выполняется дважды на одном и том же элементе `canvas`: setup → cleanup → setup. Первая очистка теряла контекст безвозвратно, а второй рендерер получал на том же канвасе уже мёртвый контекст — `getContext` возвращает тот же потерянный объект, новый не создаётся. Chrome рисует канвас с потерянным контекстом белой заливкой, и она накрывала всю страницу: сайт выглядел белым, текст Hero почти неразличим. Строка удалена, достаточно `renderer.dispose()`. Подтверждено: `contextLost: false`, `clearColor: [0,0,0,0]`.

Результаты осмотра после исправления:

- Все четыре сцены рендерятся: плита iPhone с объективом, планшет, ноутбук и ряд из трёх устройств в секции сравнения.
- Консоль чистая — ни одной ошибки и ни одного необработанного отказа за всю сессию.
- Прогресс-бар отслеживает секции, клик по точке прокручивает через `lenis.scrollTo`.
- Буфер канваса совпадает с CSS-размером, соотношение сторон учитывается.

- [x] **Внешний вид устройств исправлен.** Первый же осмотр показал плоские ярко-синие прямоугольники. Причины было три: `bodyMetalness: 0.85` **без карты окружения** — металлу нечего отражать, и корпус рендерился почти чёрным; эмиссивный экран при интенсивности 0.6 светился синей плитой; света не хватало на объём. Добавлена карта окружения `RoomEnvironment` через `PMREMGenerator`, металличность поднята до 0.62 уже осмысленно, свечение экрана снижено до 0.07, добавлен заполняющий свет, габарит кадра увеличен с 4.6 до 5.2. Отдельно: экран пришлось сделать матовым (шероховатость 0.45) — глянцевый ловил яркое пятно окружения, и на крышке MacBook это выглядело белой кляксой вместо экрана.

Выявлено, но **не** исправлено — нужно решение пользователя:

- **Силуэты устройств в разметке дублируют 3D** (отложено до Этапа 5).
- **Chrome включает автоперевод** и подменяет тексты (`iPhone 18 Pro` → «iPhone 18 Профессионал»). Это не дефект сайта, но мешает проверке.
