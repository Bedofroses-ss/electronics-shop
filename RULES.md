# RULES.md — правила работы DSH-агента для сайта-витрины

Область действия: каталог `apple-story/` и всё, что внутри него.
Всё, что вне этого каталога, регулируется `../AGENTS.md` (Flask-магазин).

## Среда

- ОС: Windows, терминал PowerShell. Никаких bash-команд, никакого WSL.
- Проверено: Node v24.21.0, npm 11.19.0. `git` в PATH отсутствует.
- Рабочая папка (единственная для записи): `C:\Users\user\Documents\electronics-shop`.
- Не создавай файлы вне рабочей папки.
- **Важно:** npm пишет кэш в `%LOCALAPPDATA%\npm-cache`, то есть вне рабочей папки. В режиме `workspace-write` это даёт `EPERM`. Требуется разовое расширение прав — см. `../AGENTS.md`.

## Песочница

- Если процесс падает с EPERM (Playwright, Chromium, именованные каналы) — остановись и попроси разовое расширение прав. Не пытайся обойти.
- Скриншоты рабочего стола недоступны.

## Язык

- Ответы — на русском.
- Код, имена файлов, команды, технические термины — латиницей.
- Все тексты контента — в `src/data/content.ts`, не в компонентах.

## Модели

- В начале ответа ставь одну метку: `[Модель: V4-Pro]` или `[Модель: V41-Flash]`.
- V4-Pro: архитектура, 3D, шейдеры, отладка, ревью.
- V41-Flash: CSS, текст, переименования, простые вопросы.
- Переключение делает пользователь. Не запрашивай подтверждений.

## Формат работы

- Работай по этапам из `docs/STAGES.md`.
- После каждого этапа: команды → stdout (кратко) → результат проверки.
- Не переходи к следующему этапу, пока текущий не подтверждён.
- Не эскалируй без причины. Сначала читай `docs/`, потом спрашивай.

## Чего не делать

- Не скачивать GLB-модели устройств. Только примитивы + постеры.
- Не эмулировать более мощную модель.
- Не задавать вопросы, ответ на который есть в `docs/`.

## Статус файлов, на которые ссылаются правила

- `docs/STAGES.md` — создан, этапы продублированы из ТЗ.
- `src/data/content.ts` — создан, все тексты и цифры только там.
- ТЗ (`TZ.md`) и референсный HTML (`reference-casquette.html`) — в корне проекта.

**Референс — собранный билд.** В `reference-casquette.html` подключены `assets/main-BeXD-873.js` и `main-ByNo8-Mi.css`, которых в поставке нет. Кода GSAP/ScrollTrigger/Lenis и стилей там физически не существует: из файла берётся только декларативный контракт (имена `data-атрибутов`, структура виджетов и секций). Тайминги и easing'и пишутся самостоятельно.

## Отступления, согласованные с пользователем

- **Playwright не используется.** Проверки через Playwright не выполнять и прав на него не запрашивать. Инструмент `browser_screenshot` в этой сессии недоступен.
- **Установка пакетов разрешена** для набора: `react`, `react-dom`, `vite`, `gsap`, `lenis`, `three`, `@react-three/fiber`. Любые другие пакеты — только с отдельного подтверждения.
- **`git` недоступен в PATH**, поэтому команды коммитов неприменимы.

## Как использовать референсный HTML

HTML от Girard-Perregaux Casquette — референс приёмов и UX, не исходник. Запрещено копировать его классы и вёрстку. Перенимаются только:

- scroll-driven анимации (GSAP + ScrollTrigger + Lenis);
- виджеты: Cursor (кастомный курсор), Progress (прогресс-бар с точками), Pins (всплывающие пины);
- `data-animation`-триггеры: `title`, `paragraph`, `fadeIn`, `imageScaleDown`, `imageParallax`, `marqueeDots`, `gridPictures`, `hoursParallax`, `watchesGenerations`;
- `data-webgl` — привязка секций к 3D-сцене.

Тексты, логотип и цвета берутся от Apple. Секции: Hero → iPhone → iPad → MacBook → Comparison → Footer. Классы и структура переписываются под React-компоненты.
